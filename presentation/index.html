Two myths decide most enterprise AI programs

An agent is a runtime.

A model, instructions, memory, tools and a control loop. That is the experience layer. It does not decide:

  1. which data is authoritative
  2. what this user may retrieve
  3. what may be written to a system of record
  4. what evidence permits a release

The second myth is that the frontier model is the architecture. Both name real capability. Neither names a production system, because capability is not the constraint — accountability is.

Why not frontier models?

The dominant constraint chooses the component.

Latency

Real-time answers in milliseconds. A frontier round trip is orders of magnitude slower.

Accuracy

On a narrow, well-labelled task, task fit beats model size.

Cost

Unit cost decides whether a workload survives its own success.

Throughput

Millions of cheap, repeatable predictions. Batch and stream, not chat.

A frontier model is not your authoritative calculator, your millisecond detector, your high-volume transaction scorer, your safety interlock, or the sole writer to your system of record.

In this workflow the detector is one configuration value: a deterministic mock, a local ONNX graph, or an Azure ML endpoint. All three satisfy one protocol, so the argument is about fit — not about which vendor is winning this quarter.

Not an argument against frontier models. An argument for fit. 6:00

Five failures that look like model problems.

None of them are fixed by a better prompt or a bigger model. You have just watched the control that closes each one.

Hallucination

A fluent answer with no source. Closed by grounding and citation validation.

Missing grounding

Improvises from training data. Closed by entitlement-aware retrieval.

Missing evaluation

Demo prompts and a subjective read. Closed by a gate that fails the build.

Security risk

Shared identity, over-broad tools. Closed by the six refusals and one writer.

Operational risk

No owner, no SLO, no rollback. Closed by the audit chain and a named owner.

The tell is the team that responds to each of these by changing the prompt or changing the model. Model intent is never proof of user authorization — authorization is enforced outside the model.

READY AI · an original field framework

Readiness is evidence, not confidence.

R · Retrieval 15%

Corpus authority, ACL tests, citation validation, freshness

E · Evaluation 20%

Golden and adversarial sets, graders, release thresholds

A · Architecture 15%

Boundaries, state, capacity, failure modes, rollback

D · Data governance 15%

Classification, lineage, residency, retention, deletion

Y · Yield operations 15%

SLOs, deployment, cost per task, incidents, value

AI trust overlay 20%

Scored across every dimension above — never separately

READY AI is an original field framework. It is not a Microsoft standard, product or official guidance. Levels: 0 absent · 1 explore · 2 engineer · 3 operate · 4 scale. Each level requires an artefact — a dataset, a test, a runbook, a signed approval.

Recommended gate: overall ≥ 60, and nothing below Level 2. 20:15

Appendix A1 · not presented

MCP standardises access to capability.
It does not grant authority.

Every tool is an API product

Owner, schema, classification, allowed operations, rate limits, audit, revocation path.

Distinct identity per tool

Least privilege, input validation, fast revocation. No shared principals.

Enforcement stays outside

Model intent is never proof of user authorization. Entra and APIM decide.

Use when asked "do you support MCP?" The answer is that MCP is a transport question and the interesting question is what the tool is allowed to do once it is reachable.

Appendix A2 · not presented

Add an agent only when it owns something no other agent owns.

When it helps

Genuinely distinct tools, context, policy or lifecycle. Domain isolation and independent release cadence.

What it costs

Coordination overhead, cascading failures, duplicated state, opaque hand-offs, an evaluation surface that grows per participant.

What it requires

Hand-off contracts, termination rules, separate identities, and system-level evaluation of the outcome.

The common mistake is one agent per organisational role. A deterministic workflow calling one agent is often the better answer — it is the answer this repository chose, and ADR-0002 records why.

Appendix A3 · not presented

Security is a topology decision, not a checkbox before launch.

The AI-specific threats

Prompt injection through retrieved content, over-broad tool permissions, state and memory leakage across users, model and index poisoning.

What actually contains them

Identity, tool contracts, network boundaries and deterministic validation. Not prompt text.

The most overlooked leak is telemetry. Redaction here happens in the log formatter, so no call site can bypass it — including one that invents a new field name tomorrow.

Appendix A4 · not presented

Tokens are one meter. They are not the outcome.

Right-size

Route to the smallest model that passes the benchmark.

Cut the work

Cache, batch, trim context, deduplicate retrieval.

Limit in the platform

Budgets, quotas, circuit breakers and per-tenant caps at the gateway.

Measure the right unit

Cost per completed task, with the correction rate beside it.

The cost ledger in this repository attributes consumption across nine services and refuses to emit a currency figure without a supplied rate card. Units are facts. Prices are the customer's.

Appendix A5 · not presented

Choose the family from the task and the non-functional needs.

Frontier

Broad reasoning, high cost — synthesis, unfamiliar tasks, orchestration.

Small language model

Bounded language and routing, low latency, edge-capable.

CNN / YOLO / ViT

Very low latency, very high throughput — detection and inspection.

Forecasting

Explainable, high throughput — demand, capacity, maintenance.

Fraud / recommendation

Millisecond scoring at volume with explicit thresholds.

Rules engine

Exact, fastest, fully explainable — eligibility, limits, calculations, writes.

Hybrid usually wins: the highest system-level task fit comes from several bounded components, not one model. Benchmark on your workload — popularity is not a selection criterion.
